### 1.2 三条实测出来的硬约束（决定了架构，别再重新讨论）

1. `api.cloudflare.com` **不发 CORS 头**，预检 `OPTIONS` 直接 400 ⇒ 浏览器/WebView 不可能"直连 API"，自建网关是唯一路径。
2. `*.workers.dev` / `*.pages.dev` **在你当前网络不可达**（DNS 给假答案、TCP 443 超时，假答案跨运行还会换）⇒ 网关必须绑你自己的域名；`acct.example.com` 实测可达。
3. 官方 API 全局限流约 1200 请求 / 5 分钟 / IP，免费 Worker 10 万请求 / 天、CPU 10 ms ⇒ 网关侧统一退避 + 首屏限次。

架构结论（`06` §2）：A = PWA + 自建 Hono Worker 网关（主交付）；B = A + Capacitor APK（同一套代码加壳，增强项）；C = Flutter 原生（**不选**，理由见 §4）。

### P9 · 请求预算：5 分钟缓存 + 合并（10-10 深夜第五段新增，本机已实测完，**线上还没生效**）

**为什么加这一阶段**：他那句是「降低网关对 cf 的请求次数，改成进 app 一次加每隔 5 分钟请求一次，能合并的请求也一起合并了」。CF 侧 1200 请求/5 分钟/IP 的限流（`09`）加上手机流量，一圈逛六屏打 22 次确实太多。

做法三层 + 两处合并，全部对齐 `CACHE_TTL_MS = 300_000`：网关 `CfClient` 读缓存与 in-flight 合并、流量时间窗按 5 分钟整格对齐（**不对齐等于没缓存**，实测 warm 轮 4 次 vs 0 次）、前端 5 分钟内存、看板三条 GraphQL 合成一条（`overview` 4 → 3 次）。`?fresh=1` + `x-gw-cache`/`x-gw-fetched-at`/`x-gw-cf-calls` 三个头把"这次到底出网没"变成可观测的，界面上那行「数据取自几点 / 从哪层拿的」就是靠它，**并且现在会真的走秒**（这一轮顺带修掉三个自己的谎：`gwMeta` 不是 reactive 导致那行压根没渲染、`dt()` 把 epoch 毫秒原样印成 `1791637506524`、"多少秒前"算死后不更新）。逐条与实测数字在 `11` §2 深夜第五段。

一处合并被实测**证伪后放弃**：`GET /zones/{z}/rulesets` 会把 custom/managed 返回成 `rules: 0`，而 entrypoint 实测有 1 条生效规则 —— 用它省 2 次请求，代价是把"有规则"显示成"0 条规则"，不做。

验收本机已过：`probe-request-budget.mjs` 三圈 **22 → 0 → 0**（两个计量口径完全对上）、冒烟 39/0、两个 tsc 干净、`check:routes`、`check:pwa` 8 项全绿、浏览器实测 `local/hit/fresh` 三态文案。

**还差两件事**：① 重新 deploy 网关 + 静态资源（账号动作，等他点头；线上不降为 0 也算正常，缓存按 isolate 分格，"5 分钟一次"是下界）；② `1dGroups` 那个"数据窗最多旧 5 分钟"的取舍他认不认 —— 界面已经把真实取数时刻显示出来了，如果他要求"刷新必须给我最新"，就把看板那条文案保留、但把 bucket 对齐换成"同一自然日内对齐"或把 TTL 调短（改 `CACHE_TTL_MS` 一个常量，两处复用）。
顺带的好处：P8 剩下的 ②（看板环比 delta，要网关多取一个前窗）现在成本几乎为零 —— 前窗那批 key 同样落在 5 分钟缓存里。

## 4. 明确不做（non-goals）

- **Flutter / Kotlin 原生 App**：`08` §7 逐文件读过 `CloudFlareAssistant`（Kotlin，无 LICENSE 正文、不能 fork）—— 它不需要网关是因为原生 HTTP 客户端不受 CORS 约束，代价是 CF 令牌明文存在手机本地。这条路线在 `06` §2 已否；我们坚持令牌只活在工作器 secret 里。
- **浏览器直连 `api.cloudflare.com`**：硬约束 1 决定了不存在这种方案，界面上也不给用户这个错觉。
- **调前端超时 / 加路由缓存**：P1 的公网并发数据已经到手（8 并发总墙钟 792ms、撞线 0 条，`09` §C7），**没有依据支持动这 25 秒**，所以这条继续不动；本地的偶发整链路卡顿不算依据。
- **历史版本源码下载**：没有公开接口（`09` §E7），Worker 详情不提供。
- **R2 / Email Routing / Turnstile / Zero Trust / D1 Time Travel**：账号未开通或产品没有公开 REST 规格（`09` §A3/A4），第一版不为其写 UI。
- **把 APK 当主交付**：`09` §C5/C6。
- **多账号的写侧**：`?account=` 只影响读。写链路（P4）第一版只在你点名的**一个**账号、一个测试 Worker 上走，不做"批量跨账号操作"这种一听就危险的事。
- **照抄同类 App 的两条端点**：`POST …/versions/{v}/deploy` → `405 code 1001`、`PATCH workers/domains/{id}` → `405 10405`，实测不可用（`08` §6.2）。

## 5. 什么叫做"做完"

四块里**三块**（流量 / Workers 版本查看与切换 / 自定义域名+DNS）在手机上真实可用，写链路在测试 Worker 上闭环过一次并落进错误分类；39 条冒烟**对着公网域名**全绿；Pages 要么有真实数据、要么保持诚实的空状态；界面任何"没有数字"都分得清是**没取到 / 取数中 / 确实没有 / 已失效的选择**这四类；多账号在**有第二个可见账号时**能真的切过去（现在只有 1 个，所以这一条仍算未验证，见 `09` §F）；账号里除了网关 Worker 与它的域名，没有我没跟你确认就创建的东西。

对照这句话的现状（10-10 深夜）：已经达成的是"39 条冒烟对着公网全绿""三块读侧有一个真实入口 `https://cf.acct.example.com`""诚实文案四态""账号里只有你确认过的那四项变更"。**还差**的是：你本人在手机上过一次首屏（P2）、版本切换/回滚在测试 Worker 上真闭环一次（P4）、Pages 那一块的数据（P5）。这四句话里任何一句没做到，我都不会把它说成"完成"。
