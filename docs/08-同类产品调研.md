## 2. `hefy2027/cf-manager`（MIT）—— 最适合当"底座参考"

Vue3 + Naive UI + Pinia 前端，`backend/`（Express 5）+ `worker/`（Hono + `wrangler.toml`）两套后端，可自部署到 CF Pages/Workers 或 Docker；支持多账号、实时配额（Workers/AI/Rendering）、Workers 与 Pages 部署、DNS、隧道、规则引擎、KV/D1/R2、Workers AI、Browser Rendering，还内置 OpenAI 兼容 API；凭据 AES 加密后存储。

对我们的价值：它证明了"`Hono Worker` 当网关 + `Vue3` 当移动端优先界面"这条技术组合是能撑起一个完整控制台的，而且**许可证允许我们读它的 API 调用组织方式**。
它的不足：Naive UI 的自适应 ≠ 手机单手操作，UI 仍要重写；功能面偏"账号管理"而不是你要的"流量 + 版本切换"深度。

### 6.1 我们确实没测的范围内端点（已补测完）

这 6 条已于 2026-10-09 深夜全打了一遍（只读，`node tools/probe-shapes6.mjs` → `docs/evidence/probe6.json`）。其中 `script-settings`、脚本级 `subdomain` 与 WAF 三阶段读取**已在 2026-10-10 接进网关白名单**（`/v1/workers/{s}/script-settings`、`/v1/workers/{s}/subdomain`、`/v1/zones/{z}/waf`），界面上能看到真数据；其余仍只是"验过形状"，没进 App：

| 端点 | 实测结果 | 结论 |

### 6.2 它用的两条"官方规格里找不到"的端点 —— 已实测，确实别跟

- `POST /accounts/{a}/workers/scripts/{s}/versions/{v}/deploy`（它源码注释自己写着 "Deploy a Worker Script version (rollback) (**beta**)"）。**实测假 worker + 假 id 打一次 → `405 {"code":1001,"error":"method_not_allowed"}`**（注意这个错误信封是 `code/error`，和 CF 标准的 `success/errors[].code` 不是一套，基本是路由级直接挡下）。正规路径仍是 `POST …/deployments`（`09` B2）。App 里不要把回滚挂在它上面。
- `PATCH /accounts/{a}/workers/domains/{id}`（改自定义域名绑定）。**实测假 id → `405 code 10405 Method not allowed for this authentication scheme`** —— 就是 `09` E6 那条"动词不对"。官方规格里这个资源只有 GET/PUT/DELETE，这条实测也对不上，**别依赖**。要做"启用/停用自定义域名"得先想清楚用 PUT 整体替换还是删重建，留到 `docs/11` §4.4 真机验。
- 还有一条我**没敢对真实 Worker 探**：`DELETE /accounts/{a}/workers/workers/{id}/versions/{v}`（它 `CloudFlareApi.kt:303` 里那个 `workers/workers` 双段路径）。原因是 `09` E1 已证 Workers 路由会把未知后缀**回落成父资源** —— 拿生产脚本试一个 DELETE 后缀，万一被解析成删整包就不可逆。对不存在的 worker 名打只得到 `10007`，说明不了后缀到底被不被识别。结论：这条按"存疑、不用"处理，正规删除版本另有路径，App 第一版根本不需要删版本。
- 顺带一个写法差异：它的 Pages 直传链是 `upload-token → assets/upload → upsert-hashes → POST deployments`，**没有 `check-missing`**。这不影响我们（wrangler 4.149 源码里 `check-missing` 明确存在，见 `03` §3.2），但说明"少调一步也能成"，所以 `check-missing` 是优化而不是必需。它同样没抄 `!size` 后缀 —— 与 `03` §3.1 的结论一致。

## 7. 逐文件读 `CloudFlareAssistant` 的源码（2026-10-10，只读、未复制任何代码）

背景：你问"能不能不要线上 Workers，靠逆向这个 APK 看它怎么搞"。结论是**不用反编译，它源码全公开**，直接读文件就是权威答案；APK 只能回答"能不能装"。以下是这次读到的东西，全部给了具体文件与行号，可复跑。

### 7.1 它**没有任何后端**，直连官方 API

- `core/network/NetworkModule.kt` 里 Retrofit 的 base 是写死的常量：`private const val BASE_URL = "https://api.cloudflare.com/client/v4/"`，OkHttp 超时 30s、`.fastFallback(true)`，日志拦截器把 `Authorization / X-Auth-Email / X-Auth-Key / X-Auth-Token / CF-Access-Client-Id / CF-Access-Client-Secret / Cookie / Set-Cookie` 都抹掉再打印。
- 递归树里按严格条件（`wrangler.toml`、`serverless`、`express`、`dockerfile`、`backend/`、`reverse-proxy` 等）筛，命中的 **9 条全是 Android 自己的界面代码**（`feature/worker/WorkerFragment.kt`、`WorkerLogsActivity.kt` 这类），没有一条是后端工程；根目录只有 `app/`（Gradle Android 工程）、`gradle/`、`.github/workflows/`、`pages-deploy-guide/`。另外名字里带 "worker" 的路径有 292 个，绝大部分是包名 `com.muort.upworker` 造成的假阳性 —— 这条我第一遍也筛错了，所以别写"仓库里 0 个 worker 文件"，要写"没有后端工程"。

**为什么它可以不要网关，而我们不行**：浏览器（含 Capacitor 的 WebView）发跨源请求要先过同源策略/CORS 预检，而 `api.cloudflare.com` 实测**不返回任何 CORS 头**（预检 `OPTIONS` 直接 400，见 `00`、`09` §C1）；OkHttp/Retrofit 是原生 HTTP 客户端，根本不参与这套机制，所以它天然不需要中继。这不是他比我们高明，是形态差异。

### 7.2 代价：CF 令牌存在手机本地

`core/util/AuthHelper.kt:20-26` 就是 `"Bearer ${account.token}"` —— 令牌是 Room `Account` 实体的一个字段，直接进 header。`app/schemas/com.muort.upworker.core.database.AppDatabase/1..11.json` 说明它有本地库并做了 11 次迁移（多账号）。**这个仓库里的 DB 有没有加密我没查到证据**（没看到 `EncryptedSharedPreferences` / `MasterKey` / Keystore 相关命名，但只 grep 了文件名，没读全 DB 模块）。对比：cf-mobile 明确用 AES-256-GCM + PBKDF2 + Keystore 硬件绑定。

这条就是我们走"网关 + 设备令牌"的核心理由，不是洁癖：**手机丢了 / 被人装个抓包工具，明文令牌就能直接读你整个账号**。网关方案里 CF 令牌只在服务端 `.dev.vars`/secret，手机上那个 `DEVICE_TOKENS` 可以单独吊销。

### 7.3 `PagesBlake3Hasher.kt` 与 wrangler 不一致 —— 别跟它

`core/crypto/PagesBlake3Hasher.kt:46-61`：`val payload = "$b64.$ext"` —— base64 和扩展名之间**插了个字面点**，注释却写"算法与 wrangler v4 / cf-manager `Be()` 对齐"。同文件 L69 的旧 SHA-256 fallback 反而注明"此处没有点"。wrangler 4.149 源码是 `path.extname(filepath).substring(1)` 后**直接拼接**（`03` §3.1）。它的单测只拿 BouncyCastle 自证，没有任何服务端返回的哈希当 fixture，所以证明不了服务端认哪种。按无点版实现，风险与症状记在 `03` §3.1。

顺带：它用 BouncyCastle `Blake3Digest(128)`，并且因为 `android.util.Base64` 与 `java.util.Base64` 在 Android/JVM 单测里行为不同，做了"探针+回落"的反射处理 —— 这段是形态经验，不是接口事实，我们不需要（我们哈希在网关侧用 Node/wrangler 生态算）。

### 7.4 实时日志（关系到风险 C3）：他给的办法是"再套一层 Worker"

`core/util/LogProxyHelper.kt` 整个文件只有 61 行，做的事很单纯：SharedPreferences 存一个自定义域名，把 `wss://tail.developers.workers.dev/xxx` 的 host 换成用户填的域名。它的文档注释原文给了两条硬信息：

1. **tail 的 wss 端点是 `wss://tail.developers.workers.dev`**，作者明确写「解决国内直连 `wss://tail.developers.workers.dev` 不稳定的问题」—— 和我们 `00` 分册测出来的 `*.workers.dev` 不可达是同一件事，第三方独立印证。
2. **中继 Worker 只需两件事**：转发到 `https://tail.developers.workers.dev`，并透传 `Sec-WebSocket-Protocol: trace-v1`。

这给了我们 C3 一条不依赖"本机能不能直连 wss"的落地路径：真要做实时日志，就在我们自己的网关上加一条 WS 中继（挂在 `cf.acct.example.com` 这类自有域名下），前端连我们的域名。

**同日（2026-10-10）我们自己量化了这两点**（`tools/probe-tail-net.mjs` → `docs/evidence/tail-reachability.json`，不带令牌、不调 `POST …/tails`）：

- 作者说的"直连不稳定"在这台机器上是**彻底不通**：`tail.developers.workers.dev` 三次独立运行分别解析到 `104.244.46.85`（Twitter 段）、`184.173.136.86`（SoftLayer 段）、`174.37.243.85`，`acct0501.workers.dev` 解析到 `122.10.85.4`，全都不是 Cloudflare 的地址，TCP 443 一律超时。还有一条更硬的：这两个完全不同的 host 拿到**同一个假 IPv6**（`2a03:2880:f1xx:83:face:b00c:0:25de`，Facebook 段）。所以"要中继"我们复现了，而且比他描述更硬 —— 假答案同一轮内稳定、跨运行会换（**不是"每次查询都不同"**，这个措辞要拿准，也别指望写 hosts 一劳永逸）。
- 自有域名一侧是好的：`acct.example.com` 一次给出 4 个答案全在 CF anycast 段（`104.21.x` / `172.67.x` / `2606:4700::`），TCP+TLS 通、出口走 IPv6，手工 WS 升级请求能穿过去拿到正常 HTTP 应答（当前回 200，因为那个 apex 现在由他现有站点接、且命中边缘缓存）。**说明"挂在你域名下的中继"这一侧没有中间层拦截**。
- 他注释里的 `trace-v1` 子协议名**仍无独立证据**（wrangler 产物里查不到），按"值得先试的方向"处理。
- 由此得出一条必须记住的坑：**本地 `wrangler dev` 测不出中继** —— 本地运行时出站用的是这台被污染的解析器，必然连不上 tail，那是假阴性。要测只能等 `docs/11` §4.1+4.2 上线后在 CF 侧测。已写进 `09` §C3 缓解栏。

### 7.5 分发面（回答"能不能直接装"）

30 个 release，最新 `CloudFlareAssistant-v7.8.5.apk` 5.7 MB、下载 141 次。**装它 = 把你的 CF API Token 交给一个无 LICENSE 正文、你无法验证构建与源码一致的第三方二进制**（`.github/workflows/release.yml` 存在，但 `keystore.properties` 写死作者本机路径，仓库里没有可复现签名）。真想试的话，用一次性、最小权限、马上能吊销的令牌，别用日常令牌 —— 这条我建议放在你决定要不要用之后再说，不催。
