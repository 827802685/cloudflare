# 14 - 界面说明与原理档案

设置页按「界面只留操作文案」瘦身（2026-10-18），这里收录被搬走或删掉的原理说明，按设置页卡片分节。界面文字与本文冲突时，以本文为准（更详细）。

---

## §1 连接：APK 直连 / 网关配置

- **APK 直连模式**：所有请求从本机直接发给 `api.cloudflare.com`，不经过网关、不需要部署任何服务。装包即用，唯一要填的是 CF API Token。
- **浏览器 / PWA 模式必须走网关**：CF 官方 API 不发 CORS 头，浏览器预检（OPTIONS）直接 400，这是实测结论（docs/06 §1），不是实现偏好。
- **网关地址必须填你自己的域名**：实测 `*.workers.dev` 在本机网络不可达（DNS 被污染到 `108.160.166.148`），自定义域名可达（docs/09 §C1）。
- **设备令牌（DEVICE_TOKENS）**：只回答「谁能用这个网关」；CF 令牌回答「用哪个账号的数据」。网关没配名单时可留空。

## §2 外观（深浅档 / 强调色 / 长列表）

- 深浅两档都是正式设计过的（语义色按各自底色重挑过对比度）。选「跟随系统」时跟着系统走；显式选浅/深会钉住。
- 强调色只换按钮、标签、焦点环这一族控件色；**卡片左沿的读数轨不受影响，仍是「橙 = 有真数 / 蓝 = 取数中」**，所以换色不会把四态编码混掉。字体不点名具体字体（只给通用族）。
- 「长列表默认显示」管的是所有「一行一项」的列表：Worker 版本与部署历史、Pages 部署历史、DNS 记录、D1 / KV / R2 左栏、KV 的 Key 表——超出条数出「展开更多」，选「全部」不折。**不跟这档走**的是计算页顶部的「每日额度」和「按 Worker 事件分布」：那两块默认只留最高的那条，是刻意的极值读数而不是分页。
- 三项偏好存在本机（`cfconsole.theme.v1`、`cfconsole.accent.v1`、`cfconsole.listCount.v1`），不上云、不影响取数请求数。

## §3 版本与更新检查

- 数据源是本仓库的 GitHub Releases（latest），回退链：**API 直连 → releases.atom 经加速 → atom 直连**。任何一级 404/超时都继续回退，全空才报错——绝不把「读不到」说成「已是最新」。
- 加速拼法（代码实际用，2026-10-20 定为唯一；对**每个**候选域名统一适用）：**用加速域名直接替换 `github.com`** —— `https://github.com/<owner>/<repo>/releases/` → `https://<加速域名>/<owner>/<repo>/releases/`。域名全部来自仓库变量，代码里不写死任何域名。
  - 兼容原理：注意 **Cloudflare 边缘会把路径里的 `//` 折叠成 `/`**（Worker 实际看到 `/https:/github.com/...`），所以归一化正则必须写成 `/^\/https?:?\/+github\.com(\/.*)$/i` 同时兼容单双斜杠。补丁前后的源码备份在 `tools/gh-proxy-backup/`。
- **换加速域名**：改仓库变量 `GH_ACCEL_BASE`（Settings → Secrets and variables → Actions → Variables）→ 重出包。它不是凭据，所以放 Variables 不放 Secrets。留空 = 直连 GitHub。
- **多域名写法**：`GH_ACCEL_BASE` 支持逗号分隔，检查更新逐个试、坏一个换下一个；但**按钮 href 只能取单个域名**——0.2.2/0.2.5 各出过一次回归：下载页 href 直接拼了整串变量（变成 `https://A,https://B/827802685/...`）。现在 `ACCEL_BASE` 固定取候选第一个（`ACCEL_BASES[0]`），并给漏写 scheme 的项补 `https://`（否则是站内相对路径，点了跳回本应用）。
- atom 兜底没有资产清单，拼不出 APK 文件名，此时下载按钮退化为「打开发行页」。
- 版本号来源：CI 出包时把发布版本（最新 tag +1，与 Release tag 同口径）经 `VITE_APP_VERSION` 注入；本地 dev 用 `package.json` 版本。这样 v0.1.5 的包检查到 v0.1.5 会正确判定「已是最新」。

## §4 账号与令牌存储（安全模型）

- **一个账号 = 一把 CF API Token**；多账号就是多把令牌并存、随时切换。账号 ID 不用手填：添加令牌时应用先打一次 `GET /accounts`，把令牌可见的账号自动发现并带出；网关侧每次请求还会校验 `?account=` 必须在这把令牌的可见集合里。
- **APK 直连模式**：令牌由「设备密钥保险箱」自动加密（AES-256-GCM），密钥首次启动随机生成、存于本机（`cfconsole.vault.devicekey.v1`），**不设口令**。密钥与密文同在本机——这道加密防「有人翻你的应用文件」，防不住「整库拖走」。要硬件级防护得换 Android Keystore 方案（`vault.ts` 预留了替换点）。
- **网页 / PWA 模式**：口令经 PBKDF2-SHA256（31 万次）派生密钥加密，口令本身不落盘、不上传，解锁后的密钥只驻留内存，关页面或「上锁」即丢——把整份 localStorage 拖走也解不开。
- **通用边界**：加密防的是「存储被拖走 / 被云备份同步」这类静态窃取；解锁（或直连模式解密）后，同源脚本照样能拿到令牌。所以：**别用 Global API Key，每把令牌只勾真正需要的权限，手机加锁屏**。
- **本机存储键清单**：`cfconsole.vault.device.v1`（直连加密账号）/ `cfconsole.vault.devicekey.v1`（直连设备密钥）/ `cfconsole.vault.v1`（网页加密账号）/ `cfconsole.config.v1`（网关地址 + 设备令牌 + 选定账号，明文——都不是凭据）/ `cfconsole.writes.v1`（本机写开关）/ `cfconsole.accounts.v1`（历史版本明文遗留，新版首启自动迁移并清除）。

## §5 写操作：两道闸门

- **本机开关**（`cfconsole.writes.v1`，默认关）：关着时写请求根本不出这台设备，网关无从知晓。
- **网关 `WRITE_ENABLED`**（仅网页模式）：本地开着而网关没放行时，请求会发到网关并被它以 `501 writesDisabled` 拒绝；处置在网关侧，在这台设备上做什么都没用。直连模式没有这道闸门，本机开关是唯一闸门。
- **写契约**（docs/12 §3 P3）：每个写动作发出前先产出完整回显（方法 / 路径 / 请求体），人确认才真发；删除类必须点名对象；写请求绝不盲重试（服务端可能已收到）；写完相关缓存立即作废。

## §6 请求预算口径

- 调度规则：进 App 拉一轮，之后每 5 分钟一轮；后台标签页不打网关，回前台只有整轮过期才补。
- **这份账只覆盖调度器发出的列表级请求**（看板 + Workers/Pages/域名清单）。详情页加载和各屏「刷新」不经调度器、不进这份账——但它们同样被本机 5 分钟缓存和网关缓存拦着。
- CF 侧真实出网次数以网关响应头 `x-gw-cf-calls` 为准，设置页累加的就是它，不是估算。直连模式没有这个响应头，按请求现算近似账（量级口径）。

## §7 写操作接通状态（2026-10-19 更新）

- **版本切换 / 回滚 / 灰度：已接通**。形状在 rin-server 上实测敲定：`POST /accounts/{a}/workers/scripts/{s}/deployments`，body `{strategy:"percentage", versions:[{version_id, percentage}], annotations?}`——annotations、两版本灰度分流（合计 100）都被 CF 接受；切到正在跑的版本是合法 no-op。网关侧已加白（`WRITE_ENABLED` 放行后可用，路由内还有版本存在性检查），直连受本机写开关管辖。
- **版本批量删除：仍未接通**。`DELETE …/versions/{v}` 的行为（能否删运行中版本、级联关系）没有实测，不做。
- **Pages 部署与回滚、写 secret、改 cron：仍未接通**——同类原因，请求形状只有反推。
- **实时日志（Workers Tail）**：tail 的 `wss://` 端点实测在本机网络不可达（DNS 污染 + TCP 443 超时，docs/09 §C1/C3），直连这条路是死的；「挂在自己域名下的中继」这层仍未实测，且不能拿本地 `wrangler dev` 测（必然假阴性）。所以不提供入口，也不暗示以后能开。

## §8 域名页（第一批瘦身，2026-10-18）

- **站点切换器**：折叠式下拉（收起时只占一个按钮的位置），按钮带当前站点状态点；展开后每项带状态点与状态文字——绿点 = zone `status: active`，黄点 = `pending`（域名还没切过来）。
- **本机写开关**：关着时新增/编辑/删除/清缓存在这台设备上就被拦下、不发请求；打开后变更请求真发、发出前逐条回显确认。网关模式里若网关 `WRITE_ENABLED` 没放行，会得到 `501 writesDisabled`，拒绝原因如实显示在确认抽屉里，不会假装成功。
- **DNS 记录交互**：整行点击 = 编辑；删除会弹确认抽屉并要求**手打记录名**（防止看错 id 删错条）。写请求统一走 preview → ConfirmSheet → 网关三步。
- **WAF / 防火墙规则**：走 `GET /zones/{z}/rulesets/phases/{phase}/entrypoint`，当前令牌即可读；写规则不在本包范围（docs/11 §4.4）。GraphQL 的 WAF 事件明细 `firewallEventsAdaptiveGroups` 被套餐挡住（免费档无 1m 分组），所以只有规则、没有命中次数。
- **缓存清理**：一次最多 30 条完整 https URL，逐条回显确认后再发；通配符一律本地拒收（docs/09 §B5 实测 CF 会真的执行非法值，所以从源头不放行）。
- **DNS 配置向导**：给自定义域名验证提示该填什么记录；判定规则是本控制台自研（非 Cloudflare 官方字段），界面会写明来源。

## §9 展示部署（demo）登录门

- 网关配置 `DEMO_PASS`（+ 可选 `DEMO_USER`）后启用：静态资源与 API 全部要求先登录（POST /login），通过后发 HttpOnly cookie（SHA-256 摘要，不落明文密码）。
- `/health` 会多报一个 `demo: true`，前端冷启动探测到后自动进入「免配置出数」：数据出口是网关的兜底 `CF_API_TOKEN`，访客无需自带令牌。
- 自用部署不配这两个变量就完全没有登录门，行为与老版本一致。`run_worker_first=["/*"]` 让静态资源也过登录门（代价：每个资源请求多一跳 Worker，演示部署可接受）。

## §10 直连层与网关层的对齐清单（2026-10-19 全量核对）

直连层（`direct.ts`）是网关 catalog 的移植，口径必须逐字一致。本轮全量 diff 补齐的三处：

1. **KV keys 游标**：`result_info.cursor` 之前被 `listify` 丢掉，两层都一样——网关还把返回包成裸数组（网关模式下 Key 列表整个是空的），直连丢 cursor（「加载下一页」永远不出现）。现在 `listify` 带 cursor、网关返回 `{ result, cursor }`、直连同形，KvPanel 的游标翻页两层都可用。
2. **Pages 多页循环**：CF 硬限 `per_page ≤ 10`（实测 `8000024 Invalid list options`），网关有逐页循环（上限 10 页），直连原本只取第 1 页——项目/部署超过 10 条静默截断。已按 `catalog.pagesList` 逐字移植 `pagesListDirect`。
3. **列表信封统一为 `{ result, total?, cursor? }`**：versions/domains 的"共 N 条"（total）与 KV 的翻页凭据（cursor）在直连模式与网关模式返回完全同形。

其余 30+ 条路由本轮逐条 diff 过：路径、参数、unwrap 方式、字段形状两层一致（WAF 三态、D1 查询 GET→POST、deployments 的 `environment=production`、脚本名在 `id` 字段等此前已对齐）。写侧仍然只有 DNS 增删改 + 清缓存四条；版本批量删除在两层都没有后端（docs/09 §B：请求体形状只有反推、没有实测），界面继续如实报 `writesDisabled`，不是直连的遗留问题。
